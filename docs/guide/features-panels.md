# 三栏面板与设置

> [← 返回 README](../../README.md) · [对话体验](features-chat.md) · [语音与多端](features-voice.md) · [架构说明](../architecture.md)

三栏工作台：**左栏**（模式切换 + 历史/模型/音色面板 + 底部「项目」区）、**中栏**（对话区 + 输入栏）、**右栏**（信息面板 / 设置面板 / 管家服务面板 / 扩展服务面板，四视图互斥替换）。以下为各面板的能力口径，实现细节见 [架构说明](../architecture.md)。

---

## 输入栏（工作模式 + 思考强度）

输入栏分为**左侧 2×2 控制区（📎 附件 / 🗜 手动压缩上下文 + 工作模式 / 思考强度）、中间加高输入框、
右侧竖排按钮（发送 / 实时语音）**三段（不再把所有控件挤在一横排），输入框默认约三行高、
自增高上限 240px：

- **工作模式**：`default`（写需确认、危险拒绝）/ `plan`（只读规划）/ `accept_edits`（文件编辑
  自动放行）/ `yolo`（全自动，危险除外），切换发 `mode.set`；
- **思考强度**：统一四档 **关闭 / 低 / 中 / 高**（后端按厂商 `THINKING_CONFIGS` 翻译成
  `thinking_budget` / `reasoning_effort`）；当前厂商无干净思考开关时（如 MiniMax）选择器置灰；切换发 `think.set`；
- **生效时机**：两项均与模型热切换同口径（引擎队列串行，正回复时于该轮结束后落地），
  即**下一条消息生效**；busy/未连接时仍可切换。初值来自 `state.get`，存于单一职责的
  `runtimeStore`。设计与协议链路详见 jarvis 侧
  [docs/fixlogs/desktop-mode-thinking-controls.md](../../../jarvis/docs/fixlogs/desktop-mode-thinking-controls.md)。

## 左栏模型面板（切换 / 添加 / 修改 / 删除）

左栏「模型」面板列表可滚动、点非当前项即切模型（`models.select`）；**双击**某项进入该模型的
配置编辑表单、**右键**某项项内出现删除按钮（交互对齐会话列表，详见下文）；列表末项固定为
「＋ 添加模型」（虚线边框区分）：

- 点击末项 → 以独立组件 `ModelForm.tsx` **整体替换**模型列表（与右栏 `SettingsPanel` 替换
  信息面板同一模式，瞬态不持久化），顶部 ← 或「取消」回列表；
- 六个字段与 REPL `/models` → 添加其他模型完全同口径：模型厂商（11 项）、模型名（必填）、
  API Key（password，留空=用全局 Key）、接口类型（openai/anthropic/dashscope/zai）、
  Base URL（留空按厂商推断）、模型类型（text/multimodal）；
- **字段区可滚动**（`ModelForm` / `VoiceForm` 共用 `.form-scroll`）：窗口不高或字段较多时
  字段区自身出滚动条（往下滑即可填完），不会溢出面板与左栏底部的「项目」区叠在一起；
  报错行与「保存 / 取消」常驻在滚动区之外，滚到任意位置都能直接提交；
- 三个下拉（模型厂商 / 接口类型 / 模型类型）走**自绘组件** `ThemedSelect.tsx`：原生 `<select>`
  展开后的列表由系统绘制（固定深灰底 + 系统蓝高亮 + 系统圆角，CSS 管不到、不随皮肤，
  还会盖住表单标签），自绘后浮层挂到 body、随三主题配色（荧光绿亮绿 / 电光蓝亮青 /
  金属银灰底黑字反相高亮，硬边方角与皮肤同族），支持 ↑↓ / Home / End / Enter / Esc
  与点击触发器或浮层之外关闭；
- 提交走 `models.add` 指令：serve 侧二次校验（模型名必填、接口类型/模型类型白名单）→ 写用户级
  `~/.jarvis/models.toml` 的 `[llm.custom_models."<name>"]`（API Key 同步系统 keyring）→ 成功后
  壳自动刷 `models.list` 并提示「模型「X」已添加」，表单关闭回列表；失败（校验/落盘）保持表单
  打开可修正，错误文案走聊天流统一出口。
- 模型项交互对齐会话列表（2026-09）：**双击**某模型 → 进入同一 `ModelForm` 的**编辑模式**
  （预填 `models.list` 该项 `config`：厂商/接口类型/Base URL/模型类型，模型名可改、API Key 恒空），
  提交走 `models.edit`；**右键**某模型 → 项内出现删除按钮，**再点才真删**（`models.remove`，
  二次确认），右键空白处或切换面板收起。删除按钮只对自定义模型渲染（内置模型后端拒绝删除）；
- 编辑模式的三个口径（与添加模式刻意不同）：**内置模型名锁定**（它来自项目级 `[llm.models]`，
  改名只会产生「幽灵模型」，输入框禁用）；**API Key 留空 = 保持原 Key**（桌面壳不回显密钥，
  不能把「未填」当清空 —— REPL 是预填明文、留空即清空）；**改的是当前运行模型时强制重建
  provider**（回执 `hot_switched`，提示「配置已更新，当前会话已按新配置重连」），端点/接口
  类型改动立即生效，其余情况只提示「配置已更新」；
- 删除语义：仅用户级 `~/.jarvis/models.toml` 的 `[llm.custom_models."<name>"]` 段真的存在时才删
  （内置模型、磁盘无该段均回 `ok=false`，防「删掉又复活」）；删的是当前模型时**不动运行中的
  provider**（不打断正在跑的回复）并提示「当前会话仍在用它，建议另选一个模型」。
- 切模型/切音色为**幂等点选**：`models.select` 写用户级配置（`last_model`，重启仍恢复）**并**在引擎线程里热切换运行中的 provider / QueryLoop（2026-09 起，见 jarvis `docs/fixlogs/model-hot-switch.md`）——落地后引擎推 `model_switched`，壳据此刷 `models.list` / 成本 / 状态，「· 当前」**立刻**移到新模型；写盘回执后到事件到达前，壳在 `leftStore` 记 `pendingModel` / `pendingVoice`：已点选项副行显「· 待生效」（虚线框）并禁用点选与悬停（`.noop`），再点同一项**不发指令、不弹提示**（否则看不出选中状态就会反复点、每点一次弹一条「已切换」）；成功提示由引擎的 `info` 事件上屏（壳不再本地弹，避免双气泡）。
  `set_model` 返回 false（写盘失败）时不记待生效，改提示「✗ 模型切换失败（未能写入用户级配置）：X」，不报假成功；引擎构造 provider 失败时只推 `warn`、不推 `model_switched`，壳保留「待生效」标记供重试。
- 切**音色**为「立即写盘 + 下次语音会话生效」（实时/半双工语音在会话内绑定音色，不热切换运行中的
  语音会话）：`voices.select` 回执为 dict `{ok, name, voice_id, linked_model, old_model}`，与终端
  `/tts-voice` 同口径——音色-模型不兼容时后端自动联动 `tts_model`，壳按 `result.ok` 判定并把
  `linked_model` 进提示（「联动 TTS 模型 X，下次语音生效」）；壳照旧记 `pendingVoice`，
  `voices.list` 的 `current` 不随点选移动。
- 音色面板（2026-09-28，音色-模型适配接入）：`voices.list` 返回**全量音色目录**（内置+自定义，
  当前置顶），副行透出「适配 X」/「联动 X」预告；交互范式对齐模型面板 —— 末项「＋ 添加音色」
  进 `VoiceForm` 表单（音色名/DashScope 音色 ID/适配模型下拉/描述，提交 `voices.add`）、**双击**自定义项
  进表单预填编辑（音色名锁定，同名 upsert 覆盖）、**右键**自定义项 → 项内删除按钮再点真删
  （`voices.delete`，内置音色不渲染删除、后端也会拒绝）；本地校验（音色名/voice_id 必填）错误
  就地显红字，后端拒绝走聊天流统一出口。

协议细节与字段口径见 [架构说明](../architecture.md#左栏模型面板切换--添加--修改--删除2026-09) 「左栏模型面板（切换 / 添加 / 修改 / 删除）」小节。

## 项目 ↔ 会话关联（左栏历史会话高亮）

左栏底部选定当前项目（工作区）后，**历史会话列表按项目归属区分标记**（2026-10，纯渲染层）：

- **当前聊天**：仍为 `.current` 填充态（半透背景 + 描边），优先级最高；
- **属于当前项目的其它会话**：标 `.in-project`——只亮**描边框**、不填充（各皮肤用自身高亮色，
  复古 CRT 皮肤下即绿色方框），一眼看出哪些会话在当前项目下；
- **其它项目的会话**：普通态，两者皆无。

判定口径：会话项 `workdir`（后端 `sessions.list` 已逐条回填）与当前项目 `currentProject.workdir`
经 `normWorkdir`（去尾部路径分隔符 + 小写，Windows 路径大小写不敏感）比较相等即为同项目；
`current` 优先于 `in-project`（当前聊天不重复标框）。无后端改动，实现在
[src/renderer/src/components/LeftSidebar.tsx](../../src/renderer/src/components/LeftSidebar.tsx) 的
`SessionItem`（`inProject` prop）+ `normWorkdir`（样式在 main.css + 三张皮肤同口径）。

> 项目工作区本身（切项目、最近项目、`project.set`）见 [架构说明](../architecture.md#左栏项目工作区切项目2026-08)。

## 管家服务（右栏面板）

标题栏右上角（设置齿轮旁）有一个 **管家服务** 按钮，点击后右栏整体切换为管家服务
面板（与设置面板同一替换机制），在面板里用表单**直接使用** Jarvis 的管家能力
（不走对话、不经模型）。入口为后续扩展预留：新增服务只需往服务清单加一项、往服务视图
映射表加一个组件、再加两份文案。按钮右上角平时没有标记，只在后端投递「感知能力
首次引导」时亮一个脉动提示点（点进面板即消，详见下文感知源一节）。

- **位置与形态**：标题栏按钮 → 右栏面板两级视图（服务清单 → 服务视图，面板内 ←
  返回信息面板）；按钮随后端连接态置灰（未连后端不可点）。实现在
  [src/renderer/src/components/ButlerPanel.tsx](../../src/renderer/src/components/ButlerPanel.tsx)
  与 [EmailServicePanel.tsx](../../src/renderer/src/components/EmailServicePanel.tsx)、
  [PerceptSourcePanel.tsx](../../src/renderer/src/components/PerceptSourcePanel.tsx)，右栏视图切换在
  `uiStore`（dashboard / settings / butler / extension 四态），面板内服务视图在单一职责的 `butlerStore`。
- **服务一·邮箱服务**（原「邮件发送」，2026-10 改名并扩展）：服务清单点「邮箱服务」→
  进入后顶部常显**当前邮箱概览卡**（当前发件邮箱 = `sender || smtp_user`、SMTP `host:port`、
  启用状态、授权码是否已配置），下方两个子标签：
  - **邮箱配置**（[EmailConfigForm.tsx](../../src/renderer/src/components/EmailConfigForm.tsx)）：
    查看/修改当前邮箱与 SMTP 信息（服务器 / 端口 / 账号 / 授权码 / 发件人 / 默认收件人 /
    启用开关），经 `email.config.get` / `email.config.set` 读写后端配置。**授权码不回显明文**，
    留空即保持原值不变；端口取值范围 1..65535（非法值本地拦截）。
  - **发送邮件**（[EmailForm.tsx](../../src/renderer/src/components/EmailForm.tsx)）：
    表单填写 **收件人 / 抄送 / 密送 / 主题 / 正文** → 点「发送」→ 经 `email.send` 指令直连
    后端 `SendEmailTool` 发送（确定性执行）。**表单点「发送」即用户确认**，后端刻意绕过
    工具默认的 ASK 权限询问；主题/正文为本地必填拦截（与后端二次校验同口径）。
  两个标签成功/失败均在面板内提示（错误内联显示、表单不关闭可重试）。
- **收件人与配置**：收件人留空时发往 `~/.jarvis/settings.toml` 的 `[email].default_recipient`；
  发信账号（SMTP 服务器/端口/授权码）同样取自该 `[email]` 表——**与终端 jarvis 共用同一份配置**。
  未配置或认证失败时后端把原文错误透传到面板内联显示。
- **首期不做附件**：渲染进程受沙箱限制，选本地文件需新增主进程 IPC + preload 能力，留待后续迭代。
- **服务二·感知源**（2026-10 阶段 9 W2）：服务清单点「感知源」→ 查看并控制 J.A.R.V.I.S
  的“工作现场感知”（前台窗口 / 目录堆积 / 仓库状况 / 重要来信 / 摄像头在场）。
  **所有源默认关**，不会因为升级或打开面板就开始采集。顶部**状态总览卡**先回答“现在
  到底在不在采”：总开关、后端宿主是否接线（后端没以 serve 模式运行时会直说“未接线”）、
  运行状态（**真正的采集判据看这一行**，接线不等于在采）、三道闸计数（emit/dedup/throttle/低显著性）、去重窗口、本地留痕开关与
  留痕文件路径（三态：有路径 / 真关显“已关闭” / 开着但总线未跑显“暂无路径”），以及
  **打扰预算**（“今日 3/10 · 待补播 2 条”）——它回答的是“jsonl 在涨为什么没声音”：
  额度用尽 / 静默时段 / 被重要度门槛判为不值得打扰，三种情形对用户都是“没声音”，
  光看总线计数区分不了；后端未启用预算时这一行**整行不显示**（不编一个 0/0）。
  另外：普通切应用默认**不会**弹气泡（权重×先验低于门槛，只留痕），这是设计而不是
  故障；真正会出声的那几条念的是**口播版**（「切到 资源管理器，jarvis 文件夹」
  而不是逐字符念路径与 `.exe`），留痕文件里仍是完整事实。
  保存与错误回执走**顶部反馈条**（`position: sticky` 钉在子返回头下方，长面板
  不滚到底也看得见——错误看不见会被误读成“开关坏了”）。三个子标签：
  - **感知源**：逐源开关（**点一下就落盘并即时生效**，没有“保存”按钮）+ 这个源采什
    么不采什么的一句话说明 + 运行账本徽标（采到几条、投递几条、是否注册进总线、是否
    连续失败自动停用与末次错误）；“观察范围”展开后能看到后端自报的目录/仓库/名单。
    本期剩下的唯一收编位「定时提醒」**只有说明没有开关**——有开关背后没人采比
    没有开关更糟（日历事件 / 系统资源已于阶段 11 接进总线，两个开关都能拨）；
  - **采集名单**：守望目录、登记仓库、发件人白名单、排除应用（四个文本域**每行一项**）
    与两个分钟阈值（停留提醒 / 摄像头空闲自动关闭，0 为关闭该特性）。只提交你**实际改过**
    的行，没动的配置不会被重写；非法分钟值本地先拦。去重窗口、显著性地板分、采样间隔
    这类调优参数**故意不做面板控件**（只能手改 `settings.toml` 的 `[percept]` 表），避免
    把隐私相关的旋钮做成可调的；
  - **最近事件**：把“到底采到了什么”摊开给你看——时间、源、一句摘要与显著性，最多 50 条，
    全量历史看留痕文件（路径在总览卡）。事件内容不做前端二次修饰，与落盘的一致才能自查。

  保存后若后端本轮没能重装配总线，面板会如实提示“已保存，但需重启后端后生效”，而不是
  假装已生效；关掉开关同时会释放 IMAP 连接与摄像头。协议细节见
  [架构说明](../architecture.md) 的 `percept.status.get` / `percept.config.set` 两行。
- **服务二·首次引导（阶段 9 W2 第 7 步）**：若你**从未对感知层做过选择**（没开过总开关、
  也没手改过 `[percept]` 配置），桌面壳连上后端后会主动告知一次：聊天区上屏一条
  **🔍 开头**的引导气泡（同时弹一次 Windows 系统通知，但**不朗读**），标题栏
  「管家服务」按钮亮脉动提示点并换上引导文案。三条保证：**只出现一次**（问过与否记在
  后端 `~/.jarvis/percept/consent.json`，重连/重启不会重复），**点进面板即清**（不是未读
  计数，壳侧不另存状态），**不代替你打开任何采集**（引导到达时仍全关，也没有“一键开启”）；
  在面板上拨一次总开关就等于表过态（记 `choice=on/off`）。

## 扩展服务（右栏面板）

标题栏右上角（「管家服务」按钮旁）有一个 **扩展服务** 按钮，点击后右栏整体切换为
扩展服务面板（与前三个视图同一替换机制），在面板里**统一管理五类扩展能力**：
**MCP 服务 / 内置工具 / 技能 / 插件 / harness 工具**。入口同样随后端连接态置灰。

- **两级形态**：面板先展示**五个分类入口页**（名称 + 一句话说明），点某一类进入该类
  详情页（面板内 ← 返回分类列表）；实现在
  [ExtensionPanel.tsx](../../src/renderer/src/components/ExtensionPanel.tsx)（外壳与分类分发）
  与 [ExtensionMcpPanel.tsx](../../src/renderer/src/components/ExtensionMcpPanel.tsx)、
  [ExtensionListPanels.tsx](../../src/renderer/src/components/ExtensionListPanels.tsx)、
  [ExtensionMarketPanels.tsx](../../src/renderer/src/components/ExtensionMarketPanels.tsx)
  三个子面板；分类视图在单一职责的 `extensionStore`，右栏视图切换在 `uiStore`
  （dashboard / settings / butler / extension 四态）。
- **五类能力**（首期完整管理口径）：
  - **MCP 服务**：增 / 删 / 改 / 启停。列表展示名称、命令/参数、传输方式、连接态与
    已暴露工具数；新增/编辑共用同一张表单（编辑时名称锁定）；删除走两步确认。
    **启停不改 `mcp.json`**（其中可能含明文 token），而是把禁用名单写入独立的
    `~/.jarvis/mcp_disabled.json`，`connect_mcp` 连接时据此过滤。
  - **内置工具**：清单查看（名称 + 一句话描述）+ 本地关键字过滤；取自引擎活动 registry。
  - **技能**：技能目录区（`~/.jarvis/skills/` 等）+ 已加载技能清单 + 本地关键字过滤。
  - **插件**：已装清单（启停 / 卸载两步确认）+ 市场搜索 → 安装。
  - **harness 工具**：已装清单（启停 / 卸载）+ 市场浏览（可展开收起）→ 安装。
- **单指令口径**：五类动作统一走一条通用指令 `extensions.exec`，以 `category`
  （mcp / tools / skills / plugins / harness）+ `action` 承载具体操作，避免为 20 个动作
  各开指令导致协议膨胀；统一返回体 `{ok, data, message}`。表单**直连后端 RPC、不走模型层**
  （与管家服务邮箱表单同口径，不污染聊天流）；写操作后自动 `reload()` 并在面板内联提示成功/失败。

## 右栏面板（六区块）

右栏信息面板（`RightSidebar.tsx`）自上而下六个区块，提醒/用量/健康走 `schedule.list` / `cost.get` /
`state.get` 与 `proactive_notify` 事件，**跨会话目标**与**副作用账本**（2026-10 阶段 10 W3）走
`tasks.exec` / `actions.exec` 两条结构化指令：

- **任务中心**：待触发提醒（⏰ + 时间 + 重复标签）与活跃截止日期（倒计时，临期标黄、
  逾期标红），以及最近一条每日简报（折叠块）；
- **跨会话目标**：把贾维斯的长线目标（“替我盯着 X，做完了告诉我”）摊开给你管。头部先
  说清**驱动器到底在不在跑**（线程在跑≠配置开了，两种情形文案不同：配置关着时目标建了也
  不会自己往下走）；每条目标显示进度、卡在哪一步、**等什么**（等待条件 / 最迟重试时刻 /
  已试次数 / 被哪些工具拦下）。就地可做的：暂停 / 继续 / 跳过等待 / 放弃 / 删除（两步确认，
  第一拍只列影响面）/ **撤销它的改动**（按目标批量回滚，逐项告诉你“撤了”还是“撤不动 + 原因”）；
  目标卡在“等你授权”时会出 **批准并重试** —— 它不是简单重试，而是顺带签一条**只限本步被拒
  工具 + 只限该目标工作目录 + 30 分钟**的授权租约（回执里会原样写明放行范围：租约只放宽
  文件类调用的确认，Bash 这类不带路径参数的调用它放宽不了，仍会被拦下如实播报）；若这一步
  没记下被拦的工具名，按钮不给放行（不签范围不明的租约）；
- **副作用账本**：把“我动过你什么”记在账上。顶部一行给回退窗口与计数（已执行/已撤销/待执行）；
  **扣住待发**是延时窗口里的预约（邮件、写文件等），显示倒计时、可一键**撤回**（它还没做任何事，
  不需要二次确认）；**最近记录**里已执行项给「回退这一轮」——粒度是**整轮**（回到本轮开始前的
  工作区）而不是单文件，第一拍会列出会影响哪些文件与“有几个新建文件会被删”，你确认后才落手；
  撤不回的项（如邮件已发出）**只写“撤不回”并附后端原因，不给按钮**；账本未启用时直说未启用。
  面板上那句提示与影响面清单都是后端原文，前端不改写。
- **会话与用量**：当前模型、token 累计（输入/输出/缓存）、**缓存命中率**（百分比，
  悬停看「命中 / 输入」明细）、**上下文窗口占比**（百分比 + 进度条，>85% 标红，悬停看
  「窗口/假设窗口 + 已用 token」，口径同 REPL `/context`）与对话轮数/消息条数，命中率与
  token 口径同 REPL `/cost`（均由后端算好后经 `cost.get` 下发，前端不重算；旧后端无上下文字段时隐藏该行）；
- **系统状态**：CPU / 内存 / 磁盘三指标卡（每 2 秒推送，CPU>85% 进度条变红）；
- **运行健康**：MCP 连接快照（成功/失败名单 + 工具数）与运行日志流（滚动 30 条）。MCP 为
  后台预热（约 9s），`init` 时快照常为 null（显“MCP 未启用”），连接落定后后端推 `mcp_ready`
  事件驱动本卡片自动刷新为真实连接态（无需重启）。

## 设置面板（独立组件）

点标题栏齿轮 ⚙ 进入，`SettingsPanel` 整体替换右栏信息面板（再点齿轮或面板内 ← 返回）：

- **外观**：主题切换（荧光绿/电光蓝/金属银，三主题同风格（Y2K 像素复古）仅配色不同，
  **荧光绿排第一且首启默认**；`<html data-theme>` + 三张皮肤覆盖块：
  theme-retro.css / theme-dark-y2k.css / theme-light-y2k.css；荧光绿=CRT 荧光绿终端、
  电光蓝=深蓝底电光蓝霓虹、金属银=铬银金属亮色，三者均配 glyph ASCII 括号牌符号与反应炉像素化）与界面语言
  （中文/English，轻量 i18n 字典）与字体（英文字体 / 中文字体各自单设，可搜索下拉枚举本机字体（Chromium Local Font Access API `queryLocalFonts`，主进程放行 `local-fonts` 权限；不可用/被拒时回落到常见字体预设），选项以自身字体预览、中文字体打「含中文」标签；未选回落主题默认等宽终端栈，代码块/工具输出始终等宽不受影响），localStorage 持久化、重启保持（用户显式选择优先，无持久化/非法值时回退默认荧光绿）；
  文本选中高亮（含改名输入框全选）同样随主题：荧光绿亮绿反相 / 电光蓝亮青反相 / 金属银黑底白字，不再出现浏览器默认蓝底；
- **语音播报**：主动播报待机 TTS 朗读开关 + 播报音量（0-100）/语速（0.5-2.0×）滑杆；
- **每日简报**：启用开关 + 简报时间（HH:MM，自绘时间选择器：小时/分钟两个下拉点选）；
- **截止日期追踪**：启用开关 + 每日检查时间（同自绘时间选择器）。

  以上三组与 serve 后端联动（真源在 jarvis settings.toml 白名单，`settings.get` 回填、
  `settings.set` 写回：外科式落盘 + 运行时生效，简报/截止日期改动额外触发调度热重注册；
  乐观更新 + 失败回滚，未连接时对应行显离线态）。

原「快捷操作」区块已拆解：🗜 手动压缩上下文按钮迁入输入栏（📎 旁，点击透传 `/compact`、结果走命令输出卡片）；曾有的 📸 主屏截屏入口因实用性低已于 2026-10 整体删除（需截图时用户自行截取后经 📎/粘贴入附件）；
📋 复制改为 AI 气泡右下角的消息级「复制」按钮（流式结束后出现）；＋新会话沿用左栏
「新建会话」，■停止回复沿用输入栏发送/停止双态按钮。语言切换 v1 覆盖静态界面文案，
运行时状态文本与后端事件消息保持中文。

架构与刷新时机见 [架构说明](../architecture.md#右栏六区块任务中心--跨会话目标--副作用账本--用量--系统状态--运行健康与设置面板)。
